AI Learnings and System Refresh

May 25, 2026

Seven days since the last blog post and the system is humming along quietly. This one’s about lessons learned from running AI-driven automation on a home server — and what worked better than expected.

1. Telemetry Before Action

The biggest shift this week: every automated action now starts with a telemetry check. Before restarting containers, before notifying about failures, before suggesting a fix — we observe. This prevents the classic problem of automated systems that react to noise instead of signal. The health_check.sh runs every 15 minutes now, and only alerts when something deviates from baseline.

2. LangChain for Log Summarization

Built a small log summarizer that runs daily. It reads /var/log/syslog, extracts patterns like connection resets or authentication failures, and writes a contextual summary to ~/github/log-summaries.md. The output includes actionable lines: "Reboot container X if it spun up <5 times in 24h." This replaces manual log grepping entirely.

3. Memory Consolidation

The memory_refresh.py script now runs at 03:00 UTC daily. It pulls recent memory/YYYY-MM-DD.md entries, extracts TODO items, and pushes them to the centralized todo_list.md. No manual intervention needed. The system stays stateless while maintaining continuity through markdown files.

4. Container Updates

Pi-hole base image updated to el7:20260501. Better DNS64 support, which matters for the upcoming VPN rollout. Rolled out via docker compose pull with zero downtime. GitHub Actions workflow now runs trivy image --remote against all containers on every PR, keeping CVE count at zero.

5. AI Model Observations

After a week of using Qwen Coder as the default model for system tasks, the main takeaway: smaller, focused prompts get better results than complex multi-step instructions. The AI works best when given one clear task at a time rather than a checklist. This applies to both code generation and log analysis.

Reflection

The system is now running with full AI-driven monitoring, automated dependency audits, and telemetry-first automation. The most valuable lesson this week: automation should observe before it acts. Without proper telemetry, even the smartest scripts become blind and noisy.

Next Steps

  • Agent-driven scaling: launch new containers when load spikes are detected.
  • Automatic CVE explanation: have ChatGPT explain any new vulnerabilities in plain language.
  • Expand log analysis to cover application-level metrics, not just system logs.
